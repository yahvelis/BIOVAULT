Un rostro es la llave.
El sistema decide.

BIOVAULT es un sistema de control de acceso que sustituye la contraseña por una muestra biométrica facial. Captura, procesa, compara contra una plantilla y toma una decisión de apertura o bloqueo — con cada intento quedando registrado.

El problema de siempre

Una contraseña se puede compartir, anotar o robar. Una tarjeta se puede prestar. Ninguna de las dos confirma que la persona frente a la puerta sea realmente quien dice ser.

Usuario + contraseña Algo que sabes — transferible
Rostro → características → comparación Algo que eres — ligado a la persona

Arquitectura

Del sensor a la decisión

Cada intento de acceso recorre la misma tubería: se adquiere una imagen, se aísla el rostro, se traduce a un vector de características, se compara contra una plantilla guardada y el resultado abre o cierra el repositorio.

Embedding

Representación numérica del rostro — un vector de 128 posiciones que un modelo aprende a extraer, no una foto.

Plantilla biométrica

El embedding de referencia guardado para un usuario en el momento del registro.

Distancia

Qué tan lejos está el embedding capturado del embedding de referencia. Menor distancia, mayor parecido.

Umbral

El límite de distancia a partir del cual el sistema deja de considerar que dos rostros coinciden.

Dos formas de preguntar

Verificación 1:1 vs. identificación 1:N

1:1

Verificación

"¿Eres quien dices ser?"

El usuario declara su identidad. El sistema busca únicamente su plantilla y compara contra esa referencia.

  1. Se selecciona un nombre registrado
  2. Se captura el rostro
  3. Se compara contra esa única plantilla
  4. Distancia ≤ umbral → acceso
1:N

Identificación

"¿Quién eres, de entre todos?"

No se declara identidad. El sistema compara contra toda la galería y busca la coincidencia más cercana.

  1. Se captura el rostro
  2. Se compara contra cada plantilla registrada
  3. Se toma la distancia mínima
  4. Mínima ≤ umbral → identificado. Si no, desconocido.

Ser la persona más parecida en la base de datos no basta — si la mejor coincidencia aún supera el umbral, el acceso se rechaza igual.

Calibración

Dos formas de fallar

FAR — Falsa aceptación

Un impostor es aceptado. El objetivo de diseño del proyecto es FAR ≤ 0.01%, aunque confirmar esa cifra exige muchas más pruebas de las que un prototipo escolar puede correr.

FRR — Falso rechazo

El usuario legítimo es rechazado. Baja si se relaja el umbral, pero eso sube el FAR — es un balance, no un máximo absoluto.

EER — Punto de equilibrio

El umbral donde FAR y FRR se cruzan. Sirve como referencia para elegir un umbral de trabajo.

Marco de referencia

Estándares considerados

ISO/IEC 19794-5

Formato de intercambio de datos de imágenes faciales — escena, propiedades fotográficas y atributos digitales.

ISO/IEC 24713-1

Arquitectura general de un sistema biométrico y la relación entre sus componentes y la aplicación que lo usa.

ISO/IEC 30107-1 / -3

Marco y terminología de detección de ataques de presentación (PAD) — y cómo evaluar su rendimiento.

ISO/IEC 29794-5

Calidad de muestras biométricas faciales — cuándo una captura es suficiente para enrolar o comparar.

Se usan como referencia conceptual para justificar decisiones de diseño; este prototipo no está certificado bajo ninguno de ellos.
